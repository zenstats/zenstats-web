# 滚动深度热力图与 Web Vitals：Web 实施规划

日期：2026-11-10。状态：滚动深度第一阶段已实现并在本地验证；历史汇总与 Core Web Vitals 待实施。

统计定义、数据模型、接口、资源预算及调研来源以[后端总方案](../../zenstats/docs/scroll-depth-and-web-vitals-plan.md)为准；本文件记录Web与Tracker工作，不复制一份独立口径。

## 已实现与验收

1. 站点设置 → 热力图 → 采集设置，打开总开关及“采集滚动深度”；“采集点击”可独立关闭。原有白名单、聚合标识、采样率和脚本 `data-heatmap="true"` 继续生效。升级后必须同步发布新的 `heatmap.js`。
2. 查看热力图，切换“滚动深度”；模式写入 `mode=scroll`，采用独立滚动页面列表，无点击的浏览也可选。选择页面／聚合标识、版本和设备后查看80段色带与触达卡；没有匹配截图时仍可查看统计、质量标记和深度滑块。
3. 首版日期限定最近 `min(raw_days, 7)` 个自然日，遵循首次启用时固定的站点时区。平均首屏线是初始视口的平均几何位置；卡片显示实际采样浏览，不是独立访客或阅读完成率。
4. 文档高度增长超过25%、报告超限或不支持的浏览不计入有效分母，延迟初始化单独标记；不同采样率混合时提示结果仅代表实际样本。
5. 管理员在采集质量页查看独立滚动队列。计数单位为报告，API 202仅表示内存接受；PV、UV、Session和常规业务事件数不受滚动报告影响。

浏览器回归覆盖无点击样本、重试身份稳定、SPA新浏览、滚动默认关闭、短页100%触达、独立开关保存、聚合截图、无截图和只读访问。真实数据库验证重复／乱序revision、页面增高、排除分母、跨站隔离、保留期和后台合并前后计数一致。

## 1. 实施顺序

1. 配合后端完成浏览生命周期、可更新报告去重和历史汇总原型。
2. 先上线可选滚动采集与7天图，再开放历史汇总日期范围。
3. 接入官方Web Vitals采集与性能面板，再开放性能历史汇总。
4. soft navigation、诊断归因、滚动目标和性能告警留给后续独立迭代。

不把“SDK接入完成”或“图表能够展示fixture”视为统计功能完成。

## 2. 滚动图工作台

入口保持当前站点热力图页面，不向Stats域名下拉重新添加热力图入口。

```text
热力图设置列表 → 新建／详情 → 查看热力图
                               ├─ 点击
                               └─ 滚动
```

- 工具栏增加点击／滚动切换，模式写入URL，刷新与分享站内地址可恢复。
- 共用路径／聚合标识、设备、版本、变体、日期和截图选择；状态变化取消旧请求，过期响应不得覆盖新选择。
- 切换到滚动时读取滚动布局列表，不能沿用仅有点击的数据列表，否则无点击浏览永远不可选。
- 图层使用80段纵向触达率色带，边缘显示百分比图例；25%、50%、75%、100%为快捷参考线。
- Hover／触摸选择位置，显示对应阈值、到达浏览数、有效采样浏览数及比例；没有逐像素精度，最多80个纵向档位。
- 平均首屏线按采样浏览的初始视口比例绘制，标明是平均几何位置，不是所有访客统一折叠线。
- 侧栏提供有效采样浏览、四档触达比例、浏览级平均最大深度、排除／截断量及数据更新时间。
- 同一截图同时适配点击与滚动图层，不为每种窗口尺寸新增截图或布局项。
- 可复用截图容器，但滚动色带建议使用独立SVG／Canvas图层，避免改动已验证的点击点绘制逻辑。

## 3. 滚动设置与数据解释

- 保持设置默认显示已配置热力图列表，新建／详情中显示点击与滚动启用状态。
- 沿用总开关、页面白名单、模板标识及例子URL；点击与滚动分别开关。
- 展示“采样页面浏览”，不使用“独立访客”“阅读完成”“按钮真实曝光”等无法保证的表述。
- 没点击、没滚动但已采集的浏览也参与分母，短页初始即可到100%。
- 页面长度和响应式布局不同会产生投影偏移；显著动态高度样本展示排除原因。
- 滚动和点击共用同次浏览抽样；采样比例变更后的混合范围显示口径提示。
- 没有截图时仍可查看触达卡片和分布曲线，不应只剩一个无法操作的截图空白框。

## 4. 性能面板

Stats新增“性能”标签，设置侧栏新增“性能监控”；性能不依赖热力图或截图配置。

总览布局：

```text
日期／主机／页面／设备／浏览器／地区／发布版本／导航类型

[ LCP P75 ]       [ INP P75 ]       [ CLS P75 ]
 各自有效样本数、Good／需改进／Poor占比、覆盖信息

[ 指标趋势：LCP / INP / CLS / FCP / TTFB ]

[ 页面排行：路径、P75、Good比例、样本量、版本 ]
```

- 首屏突出LCP、INP、CLS，FCP与TTFB作为辅助卡片或可选趋势项。
- 设备默认分组展示，移动／桌面不能只给一项混合“全站优秀”结论。
- 性能设备类型来自服务端UA，保持Stats设备口径；热力图则按视口宽度分组。不要在两个页面复用同一个设备分类函数。
- P75不是平均值，CLS没有毫秒单位；根据指标选择精度和单位。
- 无INP、不支持API、样本不足各有明确状态，缺失用“—”，不能用0或绿色卡片代替。
- 三项核心指标数据齐全且各自达到标准时才显示整体通过；小样本不显示稳定达标结论。
- 首版支持已约定维度，不自动转发Stats当前全部props／转化筛选；不支持的筛选要明确提示，不能静默忽略。
- 查询超时／资源限制提供缩短日期、减少筛选和重试操作；取消请求与过期响应处理沿用现有统计实现。
- 默认每项100个有效样本的“小样本”展示门槛是产品约定，应在帮助文案说明，不能描述为Google硬性要求。
- 不将本站RUM面板称为Search Console评分或Lighthouse跑分；同时展示采样率、导航口径、最新更新时间和聚合状态。

## 5. Tracker接入

### 滚动

- 保持现有可选heatmap资产加载；在模块内根据scroll_enabled启动滚动采样，不能依赖click监听被触发。
- 每次浏览内存生成page_view_id；初始报告→变更检查点→隐藏／pagehide报告使用同ID和递增revision。
- SPA切换先封存旧页状态，再建立新页；BFCache恢复新浏览；跨设备断点resize按总方案结束旧样本。
- 只检查根文档尺寸并合并读取任务，避免监听或读取每个元素。
- 模块加载前已关闭的页面无法补采，面板覆盖说明不能假定所有PV均已进入分母。

### 性能

- 引导脚本通过显式opt-in加载自托管vitals.js，站点配置默认关闭；设置页提供完整安装片段及接入检查。
- 将web-vitals稳定版本作为构建依赖锁定，新增独立模块打包步骤；基础Tracker的64种变体不增加新的组合维度。
- 一份文档内只注册一次官方回调，不随SPA切换重复初始化Observer。
- 使用指标实例ID与revision处理后续回调；回调时不直接读取location.href决定归属。
- BFCache恢复映射到新生命周期；不能同时由自己的恢复处理和官方库回调生成两份同义指标。
- 生产默认不启用reportAllChanges、attribution、soft navigation；将能力检测与初始化延迟写入context，避免只有“成功产生指标”的样本。
- 构建需比较基础Tracker、heatmap和vitals资产的原始／gzip／Brotli体积。官方约3KB Brotli只是库参考体积，不是整个ZenStats模块的承诺。

### 传输

- 两项业务均有单批字节数、条数、总队列长度和重试次数限制。
- hidden／pagehide使用小批次sendBeacon；返回true是排队成功，不能在界面标为数据库写入成功。
- 监听顺序必须确保官方指标回调先更新待发集合，再执行flush，避免visibilitychange时漏掉最终CLS／INP。
- 不使用unload阻塞导航；处理keepalive额度共享、sendBeacon=false、429／503、断网和重复发送。
- 数据无Cookie、无跨浏览持久标识；不发送DOM内容、完整资源URL、完整UA或自由输入字段。
